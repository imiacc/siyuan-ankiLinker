# siyuan-ankiLinker

[English](./README.md)

思源笔记闪卡单向同步 Anki 插件。

- 插件 ID / 手动安装目录名：`siyuan-ankiLinker`
- 仓库：<https://github.com/imiacc/siyuan-ankiLinker>
- 作者：`imiacc`

## 总览

插件通过 `AnkiConnect` 把思源闪卡推送到本地 Anki，再由 Anki Desktop 自己完成账号侧的同步。

同步方向严格是 **思源 → Anki**，插件不会反向写回思源。

## 运行前提

1. `Anki Desktop` 已启动。
2. 如需云端同步，请先在 Anki Desktop 登录。
3. 已安装并启用 `AnkiConnect` 插件。
4. 插件连接的本地地址类似 `http://127.0.0.1:8765`。

## 手动安装

仓库名与插件 ID 均为 `siyuan-ankiLinker`，手动安装时插件目录必须严格命名为 `siyuan-ankiLinker`。

插件只读写自己当前标签（`siyuan-anki-linker`）下的数据，不会迁移或清理旧插件变体的数据。

## 功能

- 以思源闪卡的 `cardID` 作为稳定同步身份；当 cardID 不可用时回退到 `blockID`。
- 手动从思源到本地 Anki 的单向同步，支持增量新增 / 更新 / 删除。
- 问答卡（QA）与填空卡（Cloze）可分别选择 Note Type 与字段映射。
- 从所选 Anki 模板直接读取字段名，通过下拉框选择，避免手填出错。
- 按思源文档路径前缀，把不同目录下的闪卡分流到不同 Anki 卡组。
- 同步预览、同步日志、本地映射持久化。
- 顶部操作区支持配置导出 / 导入。
- 删除判定诊断：在执行同步前查看孤儿映射与命中情况，确认删除是否安全。
- 路径规则摘要行支持编辑 / 完成两种状态，右侧操作按钮齐整对齐。

## 卡片识别规则

每张闪卡按以下顺序解析，命中即采用。

### 超级块（容器块）

如果闪卡块是思源超级块（kramdown 以 `{{{<layout>` 开头），插件**始终**走结构化问答路径：

- 第一个子块 → 正面
- 其余子块（合并） → 反面

超级块**不会**触发 cloze 检测。这样能避免子代码块里的 `==`（例如 `if (i == 0 && j == 0)`）在合并后的容器内容上被误识别为填空标记。

### 分隔符问答（单块）

非超级块的单块闪卡，使用水平分隔行切分正反面：

- `---`（三个或以上短横线）
- `***`（三个或以上星号）

### 填空（单块）

思源高亮语法会被转换为 Anki Cloze：

```md
地球离太阳最近的行星是 ==水星==。
```

会变成：

```text
地球离太阳最近的行星是 {{c1::水星}}。
```

Cloze 正则要求 `==` 两侧紧邻非空白字符，与思源自身高亮规则一致。在 cloze 检测前，行内 `` `…` `` 与围栏 ```` ```…``` ```` 代码段会被屏蔽，因此代码段内的 `==` 不会被当作 cloze 标记。

### 子块兜底

对于不是超级块、但拥有多个直接子块（例如某些列表型闪卡）的情况，当分隔符与 cloze 都未命中时，会再尝试首子块作正面、其余作反面的兜底方案。

## 同步语义

### 思源 → Anki

- 思源新增闪卡 → Anki 新增笔记。
- 思源闪卡内容变化 → 更新映射的 Anki 笔记。
- 思源闪卡消失 → 删除映射的 Anki 笔记（前提是闪卡来源可靠，见下文「删除保护」）。

### Anki → 思源

不做任何反向写入。在 Anki 中修改或删除笔记不会影响思源。下次同步时如果思源里该闪卡仍在，插件可能会重建或重新建立映射。

### 删除保护

只有当闪卡来源（SQL `cards` 表 / 闪卡块扫描）可靠时，插件才会把某条映射判定为「待删除」。如果这些来源返回空或不可靠，删除会被抑制，避免因思源侧瞬时读取失败而误删 Anki 端笔记。

## 路径分卡组

每张闪卡所属文档的 `hPath` 会按配置的规则进行 `startsWith` 匹配：

- `/英语/词汇` → `English::Vocab`
- `/数学/线性代数` → `Math::LinearAlgebra`

第一条命中的规则生效。如果都没命中，使用默认目标卡组。

建议：

- 用相对稳定的目录前缀配置规则。
- 规则尽量不要互相覆盖。
- 多条规则可能同时命中时，按配置顺序取第一个命中项。

## 模板与字段选择

插件不预设字段布局。每选定一个 Note Type，插件会：

1. 从 Anki 读取该模板。
2. 拉取其字段列表。
3. 在 UI 中以下拉框方式让你选择问答正面 / 背面（或填空正文 / 补充）字段。

这能避免手填字段名导致的 `cannot create note because it is empty` 等错误。

## 资源链接重写

写入 Anki 时，思源 `/assets/…` 引用会被重写为基于当前思源主机的绝对 URL，便于 Anki 渲染端访问图片与附件。

## 使用步骤

1. 启动本地 Anki Desktop。
2. 确认已安装并启用 `AnkiConnect`。
3. 打开插件面板。
4. 点击「检测本地连接」。
5. 点击「刷新卡组 / 模型」。
6. 选择默认卡组。
7. 选择问答模板与填空模板。
8. 在下拉框中选择目标字段。
9. （可选）添加「路径前缀 → 卡组」规则。
10. 点击「生成同步预览」。
11. 检查新增 / 更新 / 删除 / 无效条目。
12. 点击「执行同步」。
13. （可选）回到 Anki 执行正常同步上传到账号。

## 标签

插件同步出的笔记会写入若干稳定标签，即使本地映射文件丢失也能恢复匹配：

- `siyuan-anki-linker`：插件身份标签，用于定位插件所拥有的全部笔记。
- `siyuan-card:<cardID>`：每张卡的身份标签，用于在丢失映射后重新关联思源闪卡到对应的 Anki 笔记。

同时还会写入通用的 `siyuan` 标签，便于在 Anki 端做整体筛选。

## 卸载清理

完整卸载时，插件会清理自己在思源插件数据目录下创建的持久化文件：

- `settings.json`
- `mappings.json`

普通禁用、重载、版本升级**不会**触发这些清理，避免日常操作意外丢失配置。
